# kuraberu-products 完成版 UI/UX 仕様書

- 作成日: 2026-08-12
- ステータス: 確定（ユーザーレビュー反映）
- 適用範囲: 全ページ（トップ・記事一覧・記事詳細・ナビ・その他）

## 1. 目的

「ちょっと綺麗な比較ブログ」ではなく、**商品選択専用の UI を持ったサイト**にする。
デザインの見た目刷新ではなく、**情報設計**（何を・どの順に・どの強さで見せるか）を完成形に整える。

現状の問題の本質: 良い情報を出しすぎて**主役が複数ある**。
冒頭だけでも「30秒比較 → A/B候補 → 重視ポイント選択 → 条件に応じた比較結論 → 先に結論 → 差分だけ → 比較表」と判断 UI が重なっている。
→ 判断 UI を一本化し、ユーザーを 1 つの導線に乗せる。

## 2. UX 原則（サイト全体で固定・5つ）

1. **5秒で違いが分かる** — ファーストビューに「A向き / B向き / 最大の違い」だけ
2. **30秒で候補を決められる** — 差分優先で判断材料を先出し
3. **同じ情報より差分を優先する** — 「同じところを隠して、違うところを見せる」
4. **根拠はいつでも確認できるが、判断を邪魔しない** — 信頼性情報は 1 行に圧縮、詳細は後半
5. **購入誘導は明確だが、圧をかけない** — CTA は判断が固まる 2 タイミングのみ

## 3. デザイン原則

### 3.1 維持するもの（変更しない）

- 紙色背景＋濃い緑＋サーモンアクセントの現行配色
- Typography / spacing / border / **1 accent** だけで構成
- 現行の余白・カード・タイポグラフィは触りすぎない

### 3.2 やらないこと（禁止リスト）

- グラデーション、派手なバッジ、大きな角丸、カラフルな比較表
- 星評価、ランキング王冠、過剰なアイコン
- カルーセル、常時表示の巨大購入ボタン、Amazon 風の価格訴求
- 「おすすめランキング」「Amazon タイムセール」「自動生成の商品一覧」「10個以上の商品カルーセル」
- 「価格比較表を常時更新しているように見せる」演出
- 本文内に何度も広告ボタンを置く、アフィリエイトバナー

目指すべきは「**アフィリエイトサイトっぽくない比較サイト**」。

## 4. ページ別仕様

### 4.1 記事詳細ページ（最優先・S級）

#### 4.1.1 ファーストビュー（タイトル直下・最重要変更）

現状: タイトル → 「比較メモに保存」「商品情報確認日」「購入リンク確認日」「広告表示」→ ようやく30秒比較
→ 理想: タイトル直下に **「A向き / B向き / 最大の違い」の3点だけ**。5秒で記事の価値が分かる。

理想形（実装ターゲット）:

```
パンパース 新生児用、どっち？
肌への配慮を見る → 肌へのいちばん
モレ・フィットを見る → さらさらケア
大きな違いは3つ
- 肌への機能
- モレ対策
- 小さめ新生児サイズの有無
[違いを詳しく見る]        ← 差分表（比較表）へアンカー
公式情報確認済み · 2026-07-31   ← 信頼性を1行に圧縮
[♡ あとで見る]           ← 比較メモボタン（表記変更）
```

- メタ情報（確認日・広告表示・保存）はタイトル直下から外し、1行圧縮 or 後方へ
- 現在の「30秒比較」は方向性として正しい → **強化して主役にする**（他を削る）

#### 4.1.2 結論 UI の一本化（S級）

現状の重複: 「30秒比較」「条件別結論」「先に結論」が別ブロックで同じ結論を複数回説明
→ **「どっちを選ぶ？」の 1 ブロックだけ**にする。

- 30秒比較を強化（A/B カード・結論・差分・CTA を内包）し、これだけを結論 UI とする
- PriorityConclusion（条件別結論）は 30秒比較に統合するか、30秒比較が選択式を内包する形にする
- 「先に結論」ブロックは削除（30秒比較に含まれる）

#### 4.1.3 差分の視認性（S級）

- **最初の画面内に「違う3項目」を置く**（4.1.1 の理想形の通り）
- 差分表（DifferenceList）は「差分だけ → 標準表示」に昇格

#### 4.1.4 比較表（S級）

一般的な比較サイトのように全仕様を並べない。
原則: **同じところを隠して、違うところを見せる**

- **差分だけ → 標準表示**
- **全比較表 → 「すべての項目を見る」で開く**（折りたたみ）
- 「違う行」を強調、「同じ行」は弱く（グレーアウト）表示

#### 4.1.5 購入 UI（収益導線の再設計・最優先施策）

現状の問題: 購入導線は記事後半の「販売ページを検索」「楽天市場で確認（広告）」のテキストリンク主体。
→ ユーザーが「何を買うリンクか」「どちらの商品か」「なぜ今押すのか」を再解釈しないといけない。

**商品別購入カード**をサイト全体で共通コンポーネント化する。

配置: 記事冒頭の比較結論（「どっちを選ぶ？」）の直後。2枚横並び・モバイルは縦並び。

```
どちらにしますか？

┌──────────────────┐   ┌──────────────────┐
│ [商品画像]        │   │ [商品画像]        │
│ 肌へのいちばん    │   │ さらさらケア      │
│ 肌への配慮を      │   │ モレ・フィットを  │
│ 確認したい人向け  │   │ 重視する人向け    │
│                  │   │                  │
│ 楽天市場で見る → │   │ 楽天市場で見る → │
└──────────────────┘   └──────────────────┘
広告
価格・在庫は販売先でご確認ください。
```

カードに載せる要素（多くを詰めない）:

- 商品画像
- 商品名
- 「こんな人向け」の1文
- 「楽天市場」の文字（ロゴ相当は不要）
- 広告表記（カード群の下に1行）
- CTA

価格は載せない（価格・在庫は販売先で変動するため、現行の注意書きとも整合）。

**CTA 文言**（おすすめ順）:

1. 「楽天市場で商品を見る」
2. 次点: 「楽天市場で販売状況を見る」
3. 「購入する」は使わない（クリック先は商品ページであって購入確定ではないため強すぎる）

**CTA 配置は 2 箇所だけ**:

1. 「どっちを選ぶ？」の直後（= 購入カード）
2. 詳細比較を読み終えた後（記事末尾側）

何度もボタンを置くより、**判断が固まるタイミング**に置く。

#### 4.1.6 信頼性情報の階層化（A級）

現状: 記事内に「商品情報確認日」「購入リンク確認」「広告表示」「公式確認済み」「公式情報」「口コミ確認状況」「外部コンテンツ」「購入時注意」「更新履歴」「情報源一覧」「調査方法・免責事項」が散在。

→ 削除するのではなく**表と裏に分離**:

- 表: 「公式情報確認済み · 2026-08-11」の1行（ファーストビュー下部）
- 裏: 「根拠・確認方法を見る」で詳細を開く（後半に集約）

#### 4.1.7 SNS 要素の削除（A級）

「X 検索」「X 投稿」「Pinterest」等の SNS 要素は**サイトから外す**。
サイト方針が「メーカー公式情報だけで比較する」なら、SNS は UX 上もブランド上もノイズ。
「メーカー公式 → 比較 → 購入先」だけに絞る。

#### 4.1.8 長文セクションの畳み込み（B級）

根拠・口コミ・外部コンテンツ・更新履歴等で記事が非常に長い。
→ 「詳しい根拠」に畳む／後半へまとめる。判断 UI の後ろに置く。

#### 4.1.9 関連商品アフィリエイト（収益拡充・後半）

- 記事末尾に「一緒に確認される関連商品」として**2〜3件だけ**（文脈型）
- 例: 哺乳びん比較 → 替え乳首・洗浄ブラシ・消毒関連 / 鼻吸い器 → 交換ノズル・消耗品 / 抱っこひも → スタイ・よだれカバー
- 本文の途中に大量に置くのは禁止

#### 4.1.10 モバイルナビ（A級）

長文記事で現在位置・次の行動が弱い。
→ 小さな **sticky ナビ「結論 / 比較表 / 購入先」** を追加（モバイルのみ）

### 4.2 トップページ（index.astro）

現状: キャッチコピー → 記事カード → サイト方針（静かすぎる）

完成形（上から順に）:

```
Hero「暮らしの商品を、くらべる。」
↓
最近の比較（3〜6記事）
↓
何を比べますか？
紙おむつ 哺乳びん 抱っこひも 鼻吸い器 …（カテゴリチップ）
↓
このサイトの比較方法
「メーカー公式情報のみ」
「違いだけ先に確認」
「確認日を表示」
↓
記事一覧へ
```

- EC サイトみたいな巨大カテゴリ UI やカルーセルは不要
- 初訪問者に「何を比較できるサイトか」「自分が探しているカテゴリーがあるか」を判断させる

### 4.3 記事一覧ページ（articles/index.astro）

現状: 検索＋カテゴリ＋タグ（現記事数に対して重い）

完成形:

- **検索＋カテゴリチップ**だけ
- タグは記事数増加後に導入

### 4.4 ナビゲーション（BaseLayout）

- 現行: 比較メモ（機能名のまま）
- 完成形: **「比較記事 / あとで見る / このサイトについて」** に単純化
- 内部的機能名は「比較メモ」のまま、**UI 表記だけ「あとで見る」**に変更
- ユーザーは「商品を横並び比較できるのか・メモを書けるのか・記事を保存するだけなのか」が判別できない → 「あとで見る」が自然

### 4.5 その他ページ

- about / privacy / disclaimer / 404: 現行維持（内容確認のみ）
- memo: UI 表記を「あとで見る」に合わせる

## 5. 収益化設計（アフィリエイト拡充）

### 5.1 優先順位

1. **購入カード化**（4.1.5）— 最優先。リンク数を増やす前に購入 UI を完成させる
2. **Amazon 追加** — 楽天と並列「楽天市場で見る / Amazonで見る」。審査・表示ルール要確認
3. **Yahoo! ショッピング追加** — 最終形は「楽天市場 | Amazon | Yahoo!ショッピング」の3導線
4. **関連商品の文脈型アフィリエイト**（4.1.9）
5. **公式ショップ案件の探索** — ASP 経由の公式通販アフィリエイト。サイトコンセプトと相性◎

### 5.2 複数販売先の UI

3社全部を巨大ボタンにすると EC まとめサイト感が出る。
→ **「販売先で確認」+ [楽天市場] [Amazon] [Yahoo!] の静かな UI**（カード内に小リンク並列）

### 5.3 注意

- ASP・Amazon/Yahoo! の現行条件・利用可能案件は変わる → 導入時点で最新情報を確認
- Amazon アソシエイトは審査・表示ルールあり → 導入時点の規約確認必須

### 横展開方針

全記事共通コンポーネントのため、**1記事で効果確認後に横展開**（pigeon-bottle-160-240 で試行 → 全14記事）。

## 8. 検証方法

- 既存品質ゲート一式（lint / typecheck / build / test / check:rendered / check:deployment / check:external-link-syntax）を全変更でパス
- 生成 HTML のセクション順序を確認（3点構成 → 差分 → CTA → 詳細表 → 条件別結論）
- モバイル表示（縦並び・sticky ナビ）を実機/DevTools で確認
- 本番デプロイ後、公開サイト巡回（全記事 200・画像 200・外部リンク健全性）
