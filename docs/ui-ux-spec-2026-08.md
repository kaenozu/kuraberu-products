# kuraberu-products 完成版 UI/UX 仕様書

- 作成日: 2026-08-12
- ステータス: 確定（ユーザーレビュー反映）
- 適用範囲: 全ページ（トップ・記事一覧・記事詳細・ナビ・その他）

## 1. 目的

「ちょっと綺麗な比較ブログ」ではなく、**商品選択専用の UI を持ったサイト**にする。
デザインの見た目刷新ではなく、**情報設計**（何を・どの順に・どの強さで見せるか）を完成形に整える。

現状の問題の本質: 良い情報を出しすぎて**主役が複数ある**。
冒頭だけでも「30秒比較 → A/B候補 → 重視ポイント選択 → 条件に応じた比較結論 → 先に結論 → 差分だけ → 比較表」と判断 UI が重なっている。
→ 判断 UI を一本化し、ユーザーを 1 つの導線に乗せる。

## 2. UX 原則（サイト全体で固定・5つ）

1. **5秒で違いが分かる** — ファーストビューに「A向き / B向き / 最大の違い」だけ
2. **30秒で候補を決められる** — 差分優先で判断材料を先出し
3. **同じ情報より差分を優先する** — 「同じところを隠して、違うところを見せる」
4. **根拠はいつでも確認できるが、判断を邪魔しない** — 信頼性情報は 1 行に圧縮、詳細は後半
5. **購入誘導は明確だが、圧をかけない** — CTA は判断が固まる 2 タイミングのみ

## 3. デザイン原則

### 3.1 維持するもの（変更しない）

- 紙色背景＋濃い緑＋サーモンアクセントの現行配色
- Typography / spacing / border / **1 accent** だけで構成
- 現行の余白・カード・タイポグラフィは触りすぎない

### 3.2 やらないこと（禁止リスト）

- グラデーション、派手なバッジ、大きな角丸、カラフルな比較表
- 星評価、ランキング王冠、過剰なアイコン
- カルーセル、常時表示の巨大購入ボタン、Amazon 風の価格訴求
- 「おすすめランキング」「Amazon タイムセール」「自動生成の商品一覧」「10個以上の商品カルーセル」
- 「価格比較表を常時更新しているように見せる」演出
- 本文内に何度も広告ボタンを置く、アフィリエイトバナー

目指すべきは「**アフィリエイトサイトっぽくない比較サイト**」。

## 4. ページ別仕様

### 4.1 記事詳細ページ（最優先・S級）

#### 4.1.1 ファーストビュー（タイトル直下・最重要変更）

現状: タイトル → 「比較メモに保存」「商品情報確認日」「購入リンク確認日」「広告表示」→ ようやく30秒比較
→ 理想: タイトル直下に **「A向き / B向き / 最大の違い」の3点だけ**。5秒で記事の価値が分かる。

理想形（実装ターゲット）:

```
パンパース 新生児用、どっち？
肌への配慮を見る → 肌へのいちばん
モレ・フィットを見る → さらさらケア
大きな違いは3つ
- 肌への機能
- モレ対策
- 小さめ新生児サイズの有無
[違いを詳しく見る]        ← 差分表（比較表）へアンカー
✓ 公式確認済み（2026-07-31）・広告を含みます   ← 信頼性を1行に圧縮（TrustLine）
[♡ あとで見る]           ← 比較メモボタン（表記変更）
```

- メタ情報（確認日・広告表示・保存）はタイトル直下から外し、1行圧縮 or 後方へ
- 信頼表示は `TrustLine`（`✓ 公式確認済み（{productInfoCheckedAt}）・広告を含みます`）の 1 行に統一済み。旧形式（「公式情報確認済み · 日付」「広告表示：…」）はゲートが残存を検出する
- 現在の「30秒比較」は方向性として正しい → **強化して主役にする**（他を削る）

#### 4.1.2 結論 UI の一本化（S級）

現状の重複: 「30秒比較」「条件別結論」「先に結論」が別ブロックで同じ結論を複数回説明
→ **「どっちを選ぶ？」の 1 ブロックだけ**にする。

- 30秒比較を強化（A/B カード・結論・差分・CTA を内包）し、これだけを結論 UI とする
- PriorityConclusion（条件別結論）は 30秒比較に統合するか、30秒比較が選択式を内包する形にする
- 「先に結論」ブロックは削除（30秒比較に含まれる）

#### 4.1.3 差分の視認性（S級）

- **最初の画面内に「違う3項目」を置く**（4.1.1 の理想形の通り）
- 差分表（DifferenceList）は「差分だけ → 標準表示」に昇格

#### 4.1.4 比較表（S級）

一般的な比較サイトのように全仕様を並べない。
原則: **同じところを隠して、違うところを見せる**

- **差分だけ → 標準表示**
- **全比較表 → 「すべての項目を見る」で開く**（折りたたみ）
- 「違う行」を強調、「同じ行」は弱く（グレーアウト）表示

#### 4.1.5 購入 UI（収益導線の再設計・最優先施策）

現状の問題: 購入導線は記事後半の「販売ページを検索」「楽天市場で確認（広告）」のテキストリンク主体。
→ ユーザーが「何を買うリンクか」「どちらの商品か」「なぜ今押すのか」を再解釈しないといけない。

**商品別購入カード**をサイト全体で共通コンポーネント化する。

配置: 記事冒頭の比較結論（「どっちを選ぶ？」）の直後。2枚横並び・モバイルは縦並び。

```
どちらにしますか？

┌──────────────────┐   ┌──────────────────┐
│ [商品画像]        │   │ [商品画像]        │
│ 肌へのいちばん    │   │ さらさらケア      │
│ 肌への配慮を      │   │ モレ・フィットを  │
│ 確認したい人向け  │   │ 重視する人向け    │
│                  │   │                  │
│ 楽天市場で見る → │   │ 楽天市場で見る → │
└──────────────────┘   └──────────────────┘
広告
価格・在庫は販売先でご確認ください。
```

カードに載せる要素（多くを詰めない）:

- 商品画像
- 商品名
- 「こんな人向け」の1文
- 「楽天市場」の文字（ロゴ相当は不要）
- 広告表記（カード群の下に1行）
- CTA

価格は載せない（価格・在庫は販売先で変動するため、現行の注意書きとも整合）。

**CTA 文言**（おすすめ順）:

1. 「楽天市場で商品を見る」
2. 次点: 「楽天市場で販売状況を見る」
3. 「購入する」は使わない（クリック先は商品ページであって購入確定ではないため強すぎる）

**CTA 配置は 2 箇所だけ**:

1. 「どっちを選ぶ？」の直後（= 購入カード）
2. 詳細比較を読み終えた後（記事末尾側）

何度もボタンを置くより、**判断が固まるタイミング**に置く。

#### 4.1.6 信頼性情報の階層化（A級）

現状: 記事内に「商品情報確認日」「購入リンク確認」「広告表示」「公式確認済み」「公式情報」「口コミ確認状況」「外部コンテンツ」「購入時注意」「更新履歴」「情報源一覧」「調査方法・免責事項」が散在。

→ 削除するのではなく**表と裏に分離**:

- 表: 「公式情報確認済み · 2026-08-11」の1行（ファーストビュー下部）
- 裏: 「根拠・確認方法を見る」で詳細を開く（後半に集約）

#### 4.1.7 SNS 感想セクション（参考情報・B級）【2026-08-12 ユーザー指示で追加・同日改訂2回目】

「X 検索」「X 投稿」「Pinterest」等の**検索・発信要素**は載せないが、**SNS でのユーザー感想**は「参考情報」として記事後半に載せる（ユーザー指示 2026-08-12: 「SNSの感想がないけど」「埋め込みを許可されているSNSなら何でもいい」）。

- 位置: 記事後半（「購入時に確認するページ」の前 or 情報源一覧の前）
- 構成: `ExternalEmbed`（X 公式埋め込み・**autoload=そのまま表示**・**compact=会話非表示**）を **4 件・2 列グリッド**（`<div class="sns-embeds">`・モバイルは 1 列）で表示
  - **実際の投稿がその場に表示される**（引用テキストの自前カードでは不可。2026-08-12 ユーザー指摘「SNSが埋め込みになっていない。」）
  - autoload 時は表示ボタン・「直接見る」リンク・読み込みステータス・「外部コンテンツ」ラベル・プライバシー注記を非表示（投稿自体がリンクなので誘導 UI は不要: 「表示ボタンとか必要？」「埋め込みはそれ自体がリンク」）
  - 各埋め込みには「◯◯という声」タイトル + トーンラベル（good/mixed/bad）を付与
- 注記（必須）: 「SNS の感想は個人の見解で、比較の根拠にはしていません。比較はメーカー公式情報のみに基づきます」
- SNS の種類: X が主（検索で感想を収集しやすい）。YouTube/TikTok は動画の感想がある場合のみ `ExternalEmbed`（autoload）で個別に載せる
- 感想の選定: 商品名で X 検索し、公式情報と矛盾しない・特定個人への攻撃がない投稿を選ぶ。数値や仕様に触れる感想は公式情報と整合するもののみ

#### 4.1.8 長文セクションの畳み込み（B級）

根拠・口コミ・外部コンテンツ・更新履歴等で記事が非常に長い。
→ 「詳しい根拠」に畳む／後半へまとめる。判断 UI の後ろに置く。

#### 4.1.9 関連商品アフィリエイト（収益拡充・後半）

- 記事末尾に「一緒に確認される関連商品」として**2〜3件だけ**（文脈型）
- 例: 哺乳びん比較 → 替え乳首・洗浄ブラシ・消毒関連 / 鼻吸い器 → 交換ノズル・消耗品 / 抱っこひも → スタイ・よだれカバー
- 本文の途中に大量に置くのは禁止

#### 4.1.10 モバイルナビ（A級）

長文記事で現在位置・次の行動が弱い。
→ 小さな **sticky ナビ「結論 / 比較表 / 購入先」** を追加（モバイルのみ）

### 4.2 トップページ（index.astro）

現状: Hero → カテゴリ → よく比較される商品 → 最近の比較 → 診断 → サイト方針

完成形（上から順に）:

```
Hero「くらべて、選ぶ。」
↓
検索フォーム（data-top-search → /articles/?q=…）
商品名・用途・悩みで検索（例: 電気ケトル、軽い）
↓
カテゴリから探す
↓
よく比較される商品（3〜4件）→ もっと見る → /articles/
↓
最近の比較（最近追加・更新した比較、見出し付き）→ もっと見る → /articles/
↓
30秒で診断
↓
このサイトの見方
```

- 検索は記事一覧（/articles/）のクライアント側検索（article-discovery.js）に GET で受け渡す
- カードは「公式情報だけ」を前面に出すのではなく、「どっち向き？（向き: …）」の 1 行で選択を先に伝える
- EC サイトみたいな巨大カテゴリ UI やカルーセルは不要
- 初訪問者に「何を比較できるサイトか」「自分が探しているカテゴリーがあるか」を判断させる
- 「よく比較される商品」（人気・編集選定）は 3〜4 件に絞る。
  記事一覧を兼ねさせず、**意味の違う入口**として「最近の比較」（追加日順）を
  別セクション（見出し付き）で持つ。どちらも「もっと見る → /articles/」で一覧へ。
  選定パスは config/article-layout.mjs の topPage.featuredPaths が唯一の情報源。

### 4.3 記事一覧ページ（articles/index.astro）

現状: 検索＋カテゴリ＋タグ（現記事数に対して重い）

完成形:

- **検索＋カテゴリチップ**だけ
- タグは記事数増加後に導入
- カードには「向き: …」の 1 行（audiences 由来）を表示し、タイトルを開かなくても選び分けが伝わるようにする
- 検索結果カード（article-discovery.js の createCard）も同じ「向き」行を描画する（静的カードと一致させる）

### 4.4 記事内の診断誘導

- 比較記事の結論直後（「どっち向き？」判定の直後）に「まだ迷っているなら → 30秒で診断」CTA を 1 つ置く（`DiagnosisCta`）
- 哺乳瓶・おむつ記事は対応する診断カテゴリへ、それ以外は診断一覧（/tools/product-finder/）へ遷移させる
- 商品ガイドには置かない
- 仕様・品質ゲートの詳細は docs/article-layout-v3-2026-08.md「記事内の診断誘導」

### 4.5 ナビゲーション（BaseLayout）

- 現行: 比較メモ（機能名のまま）
- 完成形: **「比較記事 / あとで見る / このサイトについて」** に単純化
- 内部的機能名は「比較メモ」のまま、**UI 表記だけ「あとで見る」**に変更
- ユーザーは「商品を横並び比較できるのか・メモを書けるのか・記事を保存するだけなのか」が判別できない → 「あとで見る」が自然

### 4.6 その他ページ

- about / privacy / disclaimer / 404: 現行維持（内容確認のみ）
- memo: UI 表記を「あとで見る」に合わせる

### 4.7 レスポンシブ対応（モバイル共通レイアウト）【2026-08-18 実装】

320 / 360 / 390 / 768 / 1440px を基準に共通レイアウトを整理する。

**ヘッダー（BaseLayout）**

- デスクトップ（≥560px）: ロゴ + リンク横並び（従来どおり）
- モバイル（<560px）: **ロゴ + ☰ のみ**。`<details class="nav-toggle">` のネイティブ開閉で
  リンク群（`nav.navlinks`）を絶対配置のドロワーパネルに出す（JS 不要）。
  開閉中はアイコンが ☰ → ✕ に変わる。
- ゲート `validateHeaderNav` が全ページに details.nav-toggle + summary + nav.navlinks 構造を要求。

**記事カード（ArticleCard）**

- ≤480px: 2カラム（96px サムネイル + 本文）をやめ、**1カラム + 横長（16:9）サムネイル**にする。
- トップページは `compact` 表示（説明文・更新日を省き、画像 + タイトル + 向き のみ）。
  一覧ページは従来どおり説明文・更新日あり。

**比較表（スマホは比較カード形式）**

- ≤640px: 横スクロール表をやめ、`table.comparison` を「行 = 1 カード」に組み替える。
  thead は非表示、項目名（th[scope=row]）は全幅、各値は 2 カラム。
- 各セルには BaseLayout の `comparison-card-labels` スクリプトが商品名（列見出し）を
  `data-label` として付与し、`td::before` で表示する（JS なしでも項目名 + 値として読める段階的拡張）。
- 「根拠・確認先」列は従来どおり source-toggle で折りたたみ、開いたときは全幅表示。
- ゲート `validateComparisonCardLabels` が比較表ページへのスクリプト同梱を要求。

**その他**

- H1: ≤640px で上限を抑制（`.article-index`/`.section-intro` = `clamp(1.8rem, 8vw, 2.4rem)`、
  `.article` = `clamp(1.6rem, 7.5vw, 2.2rem)`）。長い日本語商品名でも FV がタイトルだけにならない。
- トップ検索: ≤480px で入力 + 全幅ボタンの縦積み。
- 記事カード幅: 700px → **900px**（一覧ページの右余白を解消）。

## 5. 収益化設計（アフィリエイト拡充）

### 5.1 優先順位

1. **購入カード化**（4.1.5）— 最優先。リンク数を増やす前に購入 UI を完成させる
2. **Amazon 追加** — 楽天と並列「楽天市場で見る / Amazonで見る」。審査・表示ルール要確認
3. **Yahoo! ショッピング追加** — 最終形は「楽天市場 | Amazon | Yahoo!ショッピング」の3導線
4. **関連商品の文脈型アフィリエイト**（4.1.9）
5. **公式ショップ案件の探索** — ASP 経由の公式通販アフィリエイト。サイトコンセプトと相性◎

### 5.2 複数販売先の UI

3社全部を巨大ボタンにすると EC まとめサイト感が出る。
→ **「販売先で確認」+ [楽天市場] [Amazon] [Yahoo!] の静かな UI**（カード内に小リンク並列）

### 5.3 注意

- ASP・Amazon/Yahoo! の現行条件・利用可能案件は変わる → 導入時点で最新情報を確認
- Amazon アソシエイトは審査・表示ルールあり → 導入時点の規約確認必須
