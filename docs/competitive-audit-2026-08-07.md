# 比較サイト競合監査（2026-08-07）

## 結論

現在のサイトは、1記事を「公式情報・確認状況・記事内比較・端末内メモ」まで丁寧に整理できています。一方、一般的な比較サイトと同等の入口体験にするには、カテゴリ発見、比較対象の増加、価格・販売条件の比較、第三者検証の説明量がまだ不足しています。今回の実装では、既存の静的構成を壊さず、ナビゲーションの現在地、キーボード入口、比較表のスクロール時の見出し維持、比較メモのサイトマップ登録を補強しました。

## 観測した共通パターンと優先度

- **P0**: モバイルでも「検索/カテゴリ → 比較記事 → 根拠 → 購入先」へ迷わず進めること。広告リンクと編集上の結論を分離し、価格・在庫の変動を固定値として断定しない。
- **P1**: 比較表は横スクロールしても列見出し・項目名が失われないこと。キーボード利用者が本文へ直接移動でき、現在地がナビで分かること。
- **P1**: CSPを有効にしたまま検索・絞り込みが動くこと。ページ内スクリプトはインライン実行に依存せず、Astroのバンドル対象として配信する。
- **P1**: 記事一覧は記事数が増えても検索・カテゴリ・タグで絞り込めること。URLに条件を残し、空状態を明示すること。
- **P1**: 商品同一性は、商品名・ライン・容量/サイズ・販売先URLを同一レコードで管理し、外部APIの候補選択を必須語と許可ホストで fail-closed にすること。
- **P2**: 専門家監修、独自検証、レビュー数、ランキングは、実際に根拠を取得できる場合だけ追加する。未確認の評価をUIの星や順位で補わない。
- **P2**: 端末内メモの保存内容、送信有無、削除方法をプライバシー説明に明記する。
- **P2**: 画像は権利・保存条件が確認できるものだけを使い、使わない場合はテキスト比較を優先する。静的HTMLと少量のクライアントJSを維持する。
- **P3**: カテゴリ・商品数が増えた段階で、一覧ページのページネーション/検索インデックス、構造化データの `ItemList`、価格履歴を追加検討する。

## 実装済みのP1対応

- 記事一覧の検索・絞り込みスクリプトを同一オリジンの外部ファイルとして配信し、`public/_headers` の `script-src 'self'` と矛盾しない構成にした。
- `/memo/` をsitemapへ登録し、Production後検証の必須パスにも一致させた。
- skip link、main landmark、ナビの `aria-current`、44px以上の主要操作領域を追加した。
- 比較表に列見出し・項目名のsticky表示と長い日本語の折返しを追加した。
- 比較メモのlocalStorage境界をプライバシーポリシーに、404から記事一覧への復帰導線を追加した。

## 未確認・サイト固有の残件

- 主要競合のログイン後機能、広告契約の詳細、実際のCore Web Vitalsの継続値は、公開トップページの静的確認だけでは判定していない。
- kuraberu-productsのProduction URLでの実ブラウザ受入、Cloudflareの正規経路、楽天Secrets、実CTAの販売先商品同一性は、ローカル検証ではPASSにしない。
- 運営者の法定表示に必要な実名・所在地・連絡先は、ユーザー提供値なしに生成しない。
